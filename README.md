# 汽水音乐 · Folia 模组

把本机音乐库接入 Folia 当在线音源：搜索、播放（含无损）、逐字歌词、无限续播。

## 起源

原理来自我的另一个项目 [luna-export](https://github.com/syh0119/luna-export) 的 **PC 端**部分 ——
那套工具直接从汽水音乐 PC 客户端取登录态、读本地播放队列、解密音频与歌词。

本模组把同一套原理搬进了 Folia：出口从「导出成文件」变成「实时播给 Folia」。

## 前置条件

- **Folia 0.7.20 或以上**（需要宿主的 `api.storage.paths` 来拿数据/缓存目录；更早的版本模组会拒绝启动并说明原因）
- 装好并登录 **汽水音乐 PC 客户端**

模组要用客户端的登录态和签名模块 —— 这两样都不随模组分发，会从你的客户端安装目录自动探测，装过并跑过一次就能找到。

## 安装

1. Folia → **设置 → 实验室** → 打开「模组系统」
2. 把 `soda-music` 文件夹拷到 `%APPDATA%\Folia\mods\`
3. 模组面板里启用「汽水音乐」→ 弹窗点确认

等几秒。它会自己完成：起服务 → 同步登录态 → 拉曲库 → 把书库的 **Navidrome（NAVI）页签**指到本机。

> NAVI 页签没出现就重启一次 Folia。

<details>
<summary>几个实测踩出来的坑（开发向，可不看）</summary>

- **宿主内部 id ≠ 汽水曲目 id。** 宿主的 `currentSong.id` 是**负数**（如 `-7492310190520961000`），
  和 Subsonic 的纯数字 id 不是一回事；拿它去反查一律落空，所以只认纯数字、优先取 `sourceRef.mediaId`。
- **续播为什么只能「反查」**：书库走标准 Navidrome 通道，模组界面代码不在那条路上，拿不到「用户点了哪个歌单」，
  只能用 `currentSong` 反查。所以**必须从歌单开始播**才生效。
- **`HTTP://` 用大写**：宿主预取会把 `http:` 封面地址盲目改写成 `https:`（而本机服务只有 HTTP），
  大写 scheme 能让改写跳过，Chromium 照常按 http 加载。
- **`/luna/playlist/feed/media` 走不通**（只回游标不回内容，已放弃）；`/luna/track/related`
  没有游标，翻页靠 `played_media` + 换种子，不传产量腰斩。
- 排查看 `diag.json`：设环境变量 `SODA_DIAG=1` 后重启 Folia 才会写。

</details>

## 怎么用

**从书库的 Navidrome（NAVI）页签进。**

歌单、专辑、歌手、收藏、随机播放都在里面，搜索也能搜到，播放支持无损，歌词是逐字点亮的。

不用切音源，也不用改任何设置。

**密码不用手填**：内建服务的密码是首次运行时随机生成、存在数据目录 `auth.json` 里的一串密钥，
模组会自动把它写进 Navidrome 页签的配置。想看具体值：数据目录里的 `auth.json`（日志与对外 URL 里都不再打印密钥和令牌）。

## 无限续播（可选）

命令面板执行「**开启无限续播**」—— 播放到队列倒数第二首时自动续上（每次 60 首、不重复），不用切音源；想关就执行「关闭无限续播」。开关存在模组数据目录里，重启 Folia 后自动恢复。

续播**跟着当前歌单走**：反查正在播的那首歌属于哪个歌单，优先续那个歌单里还没播过的歌；歌单自带的曲目给完了，再用它的歌当种子拉同风格，之后才落回通用推荐流。所以要**从歌单开始播**才生效（从搜索或「推荐流」接着播的歌本来就不在任何歌单里）。想知道当前歌被认成了哪个歌单，执行「无限续播状态」看最后一行。

## 出问题怎么办

| 现象 | 处理 |
|---|---|
| 提示找不到原生模块 | 客户端没跑过。启动一次客户端，再重载模组 |
| 提示登录态同步失败 | 客户端还开着 —— 先完全退出，再执行「同步汽水客户端登录态」 |
| 歌单 / 搜索为空 | 依次执行「同步汽水客户端登录态」→「刷新汽水曲库目录」 |
| NAVI 页签不出现 | 重启 Folia |
| 端口 4533 被占用 | 关掉之前单独跑过的音源服务 |
| 提示宿主没有 `api.storage.paths` | Folia 版本低于 0.7.20，升级 Folia |
| 续播没跟上歌单 / 封面不对 | 设环境变量 `SODA_DIAG=1` 后重启 Folia，看 `mods-data\soda-music\files\diag.json`（默认关闭，排查时开） |

模组面板里展开「汽水音乐」，下面有几个命令：同步登录态、刷新曲库、无限续播开关、锁定帧率、诊断卡顿。

## 数据放在哪

| 内容 | 位置 |
|---|---|
| 要保留的（设备身份、服务密钥、开关状态） | `<Folia userData>\mods-data\soda-music\files` |
| 可重建的缓存（解密音频、歌词、封面） | `<Folia userData>\mods-cache\soda-music`（可在模组面板清空） |

登录态不再明文落盘：用宿主 Electron 的 `safeStorage` 加密后写入数据目录；拿不到加密能力时只留在内存里。

旧版本的 `%APPDATA%\luna_export\soda` 会在首次启动时迁移设备身份后删掉。

## 这个模组动了什么（申报）

模组市场要求申报「模组会做的、超出普通读取之外的事」。这个模组做了这些：

| 动作 | 用途 | 说明 |
|---|---|---|
| 本机 HTTP 服务（默认 `127.0.0.1:4533`） | 给宿主当 Navidrome/Subsonic 音源 | 只监听回环地址；只接受 `Host` 为 `127.0.0.1/localhost` 且端口匹配的请求；不发任何 CORS 头 |
| 随机密钥鉴权 | `/rest/*`（数据面） | 首次运行生成、存在数据目录 `auth.json`（0600）；不再是固定口令 |
| 每次启动随机的令牌 | `/api/*` 与设置页（控制面） | 只经 rpc 交给本模组自己的 client，不落盘、不进对外 URL |
| 加载汽水客户端自带的原生模块 | 请求签名 / 设备序列号 / 解 spade 密钥 | `bdms.node` / `device.node` / `metasecml.dll`，**不随模组分发**；**在独立子进程里加载**（`native-host.cjs`），不进宿主主进程、也不改主进程的 `PATH` / 工作目录 |
| PowerShell | 调 DPAPI 解开 Chromium `Cookies` 的加密主密钥 | 一次性；登录态同步时才会跑 |
| `reg query` | 客户端启动日志里找不到安装目录时，回退读注册表卸载项来定位 | 只读 |
| 联网 | 调 `api.qishui.com` | 用该客户端的 UA；首次会以本机序列号注册一个设备身份（存在数据目录 `device.json`） |
| 写宿主设置 | `navidrome_config` / `navidrome_enabled` / `active_online_provider_id` / `visualizer_frame_rate` / `soda_music_release_hint_v1` | 这是**唯一**会改宿主配置的地方：前三个用于「把书库的 Navidrome 指到本机 / 交还音源」，`visualizer_frame_rate` 是「锁定帧率」功能（和宿主设置页改的是同一个键），最后一个是「只提示一次」的标记。Navidrome 那几项默认只在你还没配过、或本来就指向本机时才写，可在设置里关掉。写进去的密码是本机随机密钥，不是你的任何账号密码 |
| 读宿主内部 store（`folium.internals`） | 无限续播时往播放队列追加推荐 | 非公开接口（已在 `mod.json` 里声明 `folia` 版本范围）；优先走公开的 `folium.playback.enqueue`，它不可用时才退回内部 store |

权限声明：`net.fetch`（调本机服务与汽水接口）、`filesystem.data`（数据/缓存目录）、
`playback.control`（往播放队列追加）；实验接口：`omni.providers`。
